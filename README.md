# task021-coupon

优惠券规则引擎服务，仅使用标准库实现：接收订单（商品行）与一批优惠券，按固定叠加顺序（满件折 → 订单折扣 → 满减 → 无门槛直减）计算优惠后应付金额，输出命中与跳过明细，并支持在满足互斥约束的组合中推荐使应付金额最低的方案。所有金额以"分"为整数单位、折扣率以"基点"为整数表示，全程不使用浮点数。无第三方库、数据库或外部服务。

## 本地运行

```bash
go run . server --addr :8080
go run . --smoke-test
```

主要接口（请求体均为单个 JSON 对象，未知字段与多段 JSON 会被拒绝）：

- `GET /healthz`：健康检查。
- `POST /apply`：提交 `{"items":[...],"coupons":[...],"floor_rate_bps":N}`，按固定顺序结算，返回 `{"original_total","floor","payable","applied":[{id,type,reduction}],"skipped":[{id,reason}]}`。互斥组冲突返回 400。
- `POST /recommend`：请求体同 `/apply`，枚举满足互斥约束的子集，返回使应付最低的组合及 `chosen` 字段；可用券上限 16，超出返回 400。

边界约束要点：

- 互斥组：每张券可属一个互斥组（空串表示无互斥）；显式结算时同组多于一张返回 400，推荐端点自动保证每组至多一张。
- 动态满减门槛：满减门槛以"此前各阶段累计优惠后的当前总额"判定，而非原价；先行折扣可使满减被跳过。
- 底价保护：所有优惠后应付不得低于"原价 × floor_rate_bps / 10000"（四舍五入到分）；仅最终抬升一次，多出优惠不退还。
- 可用性跳过：未达件数/门槛、折扣率越界 (0,10000)、金额非正、同作用域折扣重复、同 SKU 满件折重复等计入 `skipped` 且不报错。
- 四阶段顺序固定，与传入顺序无关；单张券减免不超过当前剩余应付。

## Docker

镜像使用国内 DaoCloud Go 1.26.3 Bookworm builder 和 Alpine 3.20 runtime；支持 `linux/amd64` 与 `linux/arm64` 双架构。
